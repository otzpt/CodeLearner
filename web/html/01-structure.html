Module 1: Structure and meaning

PART 1: the skeleton, and the line that picks a mode

Every page starts the same way:

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>My page</title>
</head>
<body>
  <p>Hello.</p>
</body>
</html>

The first line looks like decoration. It selects how the page is laid out. Without it the browser switches to quirks mode, which copies the bugs of browsers from the 1990s on purpose so that very old pages keep working.

These two frames are the same page. Only the first line differs.

<body style="font-size: 28px">
<p>Paragraph text</p>
<table><tr><td>Table text</td></tr></table>

PART 2: HTML repairs mistakes instead of reporting them

A C compiler refuses a program it cannot parse. An HTML parser never refuses anything: the specification says exactly how to repair every mistake, and the page renders anyway. What you get is not always what you wrote.

PART 3: elements say what something is

These elements describe the parts of a page: <header>, <nav>, <main>, <article>, <section>, <aside>, <footer>.

<body>
  <header>
    <h1>Site name</h1>
    <nav><a href="/">Home</a> <a href="/about">About</a></nav>
  </header>
  <main>
    <article>
      <h2>A post</h2>
      <p>The text of the post.</p>
    </article>
  </main>
  <footer>Contact details</footer>
</body>

On screen they look like nothing in particular:

Open DevTools on that frame and look at the Accessibility pane: main is a landmark, and a screen reader can jump straight to it. The div is generic and has nothing to jump to.

  • One visible <main> per page.
  • Pick a heading level by its place in the outline, not by how big it looks. Size is CSS's job.
  • <strong> means important and <em> means stressed. <b> and <i> only change the look.
  • Use <div> when there is no meaning to express, only something to style.

EXERCISE 1

You write a <div> inside a <p>. How many elements end up inside the paragraph?

Answer

None. The parser closes the paragraph when it reaches the div, as the red outline showed.

Which single line keeps a page out of quirks mode?

Answer

<!doctype html> It has to be first in the file.

An <h2> looks too big, so you change it to <h4>. Good idea?

Answer

No. The level describes the outline. Change the size with CSS.

Challenge

Write a file called about.html and open it in your browser.

Input: nothing to type, the file is the program.

The result must be:

  • The browser tab says About me.
  • The page shows, in order: a main heading, a paragraph, a second-level heading Hobbies, a paragraph, and a footer line.
  • Inspect shows header, main and footer elements, and the html element has a lang attribute.
Example solution (one way of getting there) 
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>About me</title>
</head>
<body>
  <header>
    <h1>Ana Silva</h1>
  </header>
  <main>
    <p>I am learning HTML.</p>
    <section>
      <h2>Hobbies</h2>
      <p>Chess and cycling.</p>
    </section>
  </main>
  <footer>Written by hand.</footer>
</body>
</html>

SUMMARY

  • <!doctype html> selects standards mode. Forget it and the layout rules change silently.
  • HTML never reports an error. It repairs, and the repair may not be what you meant.
  • Inspect shows the tree the browser built, which is the one that counts.
  • Elements describe meaning. Their look belongs to CSS.
